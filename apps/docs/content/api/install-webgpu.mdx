---
title: installWebGPU
description: Install navigator.gpu and the WebGPU flag constants on a worklet runtime.
---

On a worklet runtime, neither `navigator.gpu`, nor the `RNWebGPU` object, nor the WebGPU flag constants are available by default.
Call `installWebGPU()` once at the top of a worklet to install the needed globals for that runtime: `navigator.gpu`, `RNWebGPU` (for the native helpers such as `createVideoFrameFromNativeBuffer`), plus `GPUBufferUsage`, `GPUTextureUsage`, `GPUShaderStage`, `GPUColorWrite`, and `GPUMapMode`.

On the JS thread these are already installed when the native module loads; calling `installWebGPU()` there is a safe no-op. See [Threading](/docs/getting-started/threading) for the rules on what runs where.

## Usage

### UI thread worklet

```tsx twoslash
import type { RNCanvasContext } from "react-native-webgpu";
declare const device: GPUDevice;
declare const context: RNCanvasContext;
declare const pipeline: GPURenderPipeline;
// ---cut---
import { installWebGPU } from "react-native-webgpu";
import { runOnUI } from "react-native-worklets";

const renderOnUI = (
  device: GPUDevice,
  context: RNCanvasContext,
  pipeline: GPURenderPipeline,
) => {
  "worklet";
  installWebGPU();

  const encoder = device.createCommandEncoder();
  const pass = encoder.beginRenderPass({
    colorAttachments: [{
      view: context.getCurrentTexture().createView(),
      clearValue: [0, 0, 0, 1],
      loadOp: "clear",
      storeOp: "store",
    }],
  });
  pass.setPipeline(pipeline);
  pass.draw(3);
  pass.end();

  device.queue.submit([encoder.finish()]);
  context.present();
};

// Create the device on the JS thread, pass the handles to the worklet
runOnUI(renderOnUI)(device, context, pipeline);
```

### Dedicated worklet runtime

```tsx twoslash
declare const device: GPUDevice;
// ---cut---
import { createWorkletRuntime, runOnRuntime } from "react-native-worklets";
import { installWebGPU } from "react-native-webgpu";

const runtime = createWorkletRuntime({ name: "gpu" });

const gpuWork = (device: GPUDevice) => {
  "worklet";
  installWebGPU();

  const buffer = device.createBuffer({
    size: 256,
    usage: GPUBufferUsage.COPY_DST | GPUBufferUsage.MAP_READ,
  });
  // …
};

runOnRuntime(runtime, gpuWork)(device);
```

### navigator.gpu on a worklet runtime

After `installWebGPU()`, `navigator.gpu` is available inside the worklet:

```tsx twoslash
import { installWebGPU } from "react-native-webgpu";
import { runOnUI } from "react-native-worklets";

runOnUI(() => {
  "worklet";
  installWebGPU();
  const format = navigator.gpu.getPreferredCanvasFormat();
  navigator.gpu.requestAdapter().then((adapter) => {
    // …
  });
})();
```

<Callout type="warn">
  On `react-native-worklets` versions before 0.13.0, write `globalThis.navigator` instead of a bare `navigator`. Older versions of the Worklets babel plugin capture the main runtime's `navigator` object by closure instead of reading the one installed on the worklet runtime.
</Callout>

Creating a device on a worklet runtime works, but is not recommended: spontaneous device events are only delivered for devices created on the main JS runtime.
- `device.lost` read on a worklet runtime returns a promise that never settles, unless the device is already lost at that point, in which case it resolves normally.
- `uncapturederror` listeners registered on a device created on a worklet runtime never fire.

Create the device on the JS thread, attach the handlers there, and pass the device into the worklet. Request-style promises (`requestAdapter`, `requestDevice`, `mapAsync`, ...) always settle on the runtime that called them.
