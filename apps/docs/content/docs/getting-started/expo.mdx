The React Native WebGPU Expo template includes raw WebGPU, Three.js, and React Three Fiber examples for iOS, Android, and web.

## Create a project

```npm
npx create-expo-app@latest my-webgpu-app --template https://github.com/wcandillon/react-native-webgpu/tree/main/apps/expo-webgpu
```

Open the app and choose an example from the menu:

- **WebGPU triangle** uses `react-native-webgpu` directly and renders WGSL without a 3D framework.
- **Three.js** imports `three/webgpu` and creates the scene imperatively.
- **React Three Fiber** uses declarative JSX with the standard Fiber module build.

The template installs the required Reanimated and Worklets peers, enables the `react-native-webgpu` config plugin, and includes the Metro resolver used by the React Three Fiber example.

## Config plugin

`react-native-webgpu` ships its own [Expo config plugin](https://docs.expo.dev/config-plugins/introduction/). Add it to the `plugins` array of your app config:

```json title="app.json"
{
  "expo": {
    "plugins": ["react-native-webgpu"]
  }
}
```

The plugin configures both native projects:

**iOS:** it disables **Metal API Validation** in the Xcode scheme, which is required to run WebGPU on the **iOS Simulator** (see [Troubleshooting](/docs/getting-started/installation#troubleshooting)). It changes nothing for release builds.

**Android:** it raises the app's `minSdkVersion` to 26, the minimum the library supports (Expo's default is 24). A higher value is kept.

With [Continuous Native Generation](https://docs.expo.dev/workflow/continuous-native-generation/), `npx expo prebuild --clean` regenerates the native projects, so settings changed by hand do not stick; the config plugin re-applies both on every prebuild.
