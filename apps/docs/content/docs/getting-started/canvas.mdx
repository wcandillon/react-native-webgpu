The [`Canvas`](/api/canvas) component is where you can access a WebGPU context and render pixels.
The API is symmetric with its Web counterpart, with a few differences.
For instance on React Native you must call `context.present()` after every `device.queue.submit()` to present the frame to the screen.

On Android, the canvas is backed by a regular view by default. The [Android rendering options](/api/canvas#android-rendering-options) explain the trade-offs and how to pick a faster one.

| Web concept | React Native WebGPU |
| ----------- | --------------------- |
| `<canvas>` in HTML | `<Canvas>` view |
| `canvas.getContext("webgpu")` | `ref.current.getContext("webgpu")` |
| Browser presents frames | You call `context.present()` after submit |

## Basic usage

Mount a `Canvas`, keep a ref, and read the WebGPU context once the view is laid out:

```tsx twoslash
import { useEffect, useRef } from "react";
import { StyleSheet, View } from "react-native";
import { Canvas, type CanvasRef } from "react-native-webgpu";

export function Scene() {
  const ref = useRef<CanvasRef>(null);

  useEffect(() => {
    const context = ref.current?.getContext("webgpu");
    if (!context) return;

    // request device, configure context, start render loop…
  }, []);

  return (
    <View style={{ flex: 1 }}>
      <Canvas ref={ref} style={StyleSheet.absoluteFill} />
    </View>
  );
}
```

`getContext("webgpu")` is **synchronous**, like on the web. If the ref is not ready yet (zero layout size), retry on the next frame with `requestAnimationFrame`.

## Frame presentations

On the Web, the browser swaps your rendered frame to the screen automatically when you submit GPU commands. In React Native there is no automatic swap: presentation is a manual step. After you submit your commands to the queue, call `present()` on the context to display the frame.

```tsx twoslash
import type { RNCanvasContext } from "react-native-webgpu";
declare const device: GPUDevice;
declare const encoder: GPUCommandEncoder;
declare const context: RNCanvasContext;
// ---cut---
device.queue.submit([encoder.finish()]);
context.present(); // React Native only
```

`present()` is a React Native only method (it is not part of the Web WebGPU spec). It runs **synchronously** on the calling thread, so the frame is presented from whichever thread did the rendering. This works the same on every runtime: the main JS runtime, the UI thread, and dedicated worklet runtimes. Always call it after `submit()`, never before.

Your loop sets the frame rate.
A loop on the Reanimated UI runtime or on a worklet runtime (see [Worklets](/docs/integrations/worklets)) runs at the display's rate, 120 Hz on a ProMotion iPhone or iPad, while React Native's `requestAnimationFrame` on the JS thread runs at 60 Hz on iOS.
An app created from an Expo or React Native template before React Native 0.82 may still carry iOS's 60 Hz cap for iPhone: [Reanimated's performance guide](https://docs.swmansion.com/react-native-reanimated/docs/guides/performance/#-enable-120-fps) covers the `Info.plist` opt-in.

## Pixel density

Just like on the Web, a canvas has two independent sizes:

- `clientWidth` / `clientHeight` are the on-screen (layout) size in logical points. They follow the view's layout and update automatically when it resizes.
- `width` / `height` are the drawing-buffer size in physical pixels. This is the resolution WebGPU actually renders at.

The drawing buffer is **not** scaled to the device pixel ratio by default, exactly as on the Web. To render crisply on high-density screens, set the buffer size to the layout size multiplied by the pixel ratio. `PixelRatio.get()` is the React Native equivalent of `window.devicePixelRatio`.

```tsx twoslash
import { PixelRatio } from "react-native";
import type { RNCanvasContext } from "react-native-webgpu";
declare const context: RNCanvasContext;
// ---cut---
const canvas = context.canvas as HTMLCanvasElement;
canvas.width = canvas.clientWidth * PixelRatio.get();
canvas.height = canvas.clientHeight * PixelRatio.get();
```

Because `clientWidth` / `clientHeight` track layout, recompute the buffer size whenever they change (for example on rotation or a resize).

## Transparency

To render the canvas over the React Native views beneath it, configure the context with `alphaMode: "premultiplied"` and clear with a color whose alpha is `0`, so that WebGPU produces a transparent frame:

```tsx
<Canvas ref={ref} style={StyleSheet.absoluteFill} />
```

<Callout type="info" title="Platform note">
On iOS `alphaMode` alone controls it. On Android the `alphaMode` passed to `configure()` is ignored: the backing view decides, and the default `TextureView` composites with alpha unless `android={{ opaque: true }}` asks it not to, while a `SurfaceView` is opaque unless asked otherwise. See the [Android rendering options](/api/canvas#android-rendering-options).
</Callout>
